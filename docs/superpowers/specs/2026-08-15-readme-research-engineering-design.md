# README Research-Engineering Positioning

## Goal

Position the repository for technical recruiters and research supervisors as a
reproducible computer-vision engineering project, rather than as a bare course
submission.

## Audience

- Technical recruiters assessing applied machine-learning and software
  engineering capability.
- Research supervisors assessing methodological clarity, reproducibility, and
  the traceability of experimental evidence.

## README structure

1. A concise title, value proposition, and project summary.
2. A credibility section explaining the uniform pipeline, automatic scene
   geometry, temporal lane-change confirmation, and auditable run artifacts.
3. A compact end-to-end pipeline description and technology stack.
4. Reproducible setup and execution commands.
5. A results-and-evidence section that distinguishes committed JSON evidence
   from locally retained MP4 renderings that exceed GitHub's normal file limit.
6. Clear scope boundaries and repository layout.

## Repository metadata

Set the GitHub description to:

> Reproducible computer-vision pipeline for counting completed vehicle lane changes from video.

## Constraints

- Preserve the factual behavior of the existing pipeline.
- Keep the README in English for an international technical and academic
  audience.
- Do not claim that the large annotated MP4 renderings are stored in GitHub.
- Keep the quick-start path short and executable.

## Validation

- Verify README headings, code blocks, and file references match the working
  repository.
- Verify the GitHub description after it is updated.
